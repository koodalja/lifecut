# 인생네컷 설계도

## 1. 목표

서버 프로그램을 따로 만들지 않고 HTML·CSS·순수 JavaScript 파일만으로 웹서비스를 만듭니다. 사진 파일을 보관하는 기능에만 Supabase Storage(사진을 인터넷에 저장하는 공간)를 사용합니다. 브라우저에서 카메라 촬영과 사진 편집을 처리하고, 완성한 사진을 Storage에 올린 뒤 QR 코드(휴대폰 카메라로 읽어 사진 주소를 여는 네모 무늬)로 받을 수 있게 합니다.

## 2. 세 층 구조

| 층 | 맡는 일 | 파일 |
|---|---|---|
| 화면 층 | 버튼, 촬영 화면, 결과 화면을 보여 주고 휴대폰 세로 화면에 맞춥니다. | `index.html`, `style.css`, `js/app.js` |
| 기능 층 | 카메라를 켜고 사진을 찍습니다. 사진을 이어 붙이고 필터를 적용하며, `js/app.js`의 `initApp()`이 화면 동작을 연결합니다. | `js/app.js`(1단계), `js/camera.js`와 `js/frame.js`(확장 A부터), `js/filters.js`(확장 B부터) |
| 저장 층 | 공개 설정으로 Supabase에 연결하고 완성 사진을 보관해 QR 코드가 가리킬 주소를 만듭니다. | `js/config.js`(확장 C부터), `js/upload.js`(확장 C부터), Supabase Storage의 `photos` 버킷(사진 보관 공간) |

브라우저에서 촬영과 편집을 처리하므로 별도의 서버 프로그램은 두지 않습니다. Supabase는 사진 파일을 보관하는 용도로만 사용합니다.

## 3. 화면 흐름

1. **컷 수 고르기** — 확장 A부터 작은 프레임 그림이 있는 2컷 또는 4컷 버튼을 누릅니다. 1단계에서는 컷 선택 없이 한 장을 촬영합니다.
2. **촬영하기** — 1단계에서는 시작 버튼을 눌러 5초 뒤 한 장을 찍습니다. 확장 A부터는 시작 버튼을 한 번 눌러 선택한 수만큼 5초 카운트다운과 촬영을 반복하고, 촬영 사이에는 0.7초 쉽니다. 현재 진행 수와 찍힌 사진 미리보기를 보여 줍니다.
3. **결과 확인하기** — 1단계에서는 촬영한 사진을 화면에서 확인합니다. 확장 A부터 촬영 사진을 4:3 비율로 흰 세로 프레임에 위에서부터 놓고, 아래에 `인생네컷`과 오늘 날짜를 표시합니다. 처음으로 버튼은 컷 선택 화면으로 돌아갑니다.
4. **필터 고르기** — 확장 B부터 결과 화면에서 원본, 흑백, 세피아, 따뜻하게, 시원하게, 화사하게 중 하나를 고릅니다. 사진 부분만 즉시 바뀌고 흰 프레임 바탕과 글씨는 그대로입니다. 원본 버튼으로 돌아갈 수 있습니다.
5. **휴대폰으로 받기** — 확장 C부터 결과 사진을 Supabase Storage에 올리고, 사진 주소를 QR 코드로 보여 줍니다.

## 4. 부품과 함수

| 용어 | 쉬운 뜻 |
|---|---|
| `Promise` | 카메라 연결이나 업로드처럼 시간이 걸리는 작업이 끝난 뒤 결과를 받는 방식 |
| `MediaStream` | 카메라에서 들어오는 영상 정보 |
| `HTMLCanvasElement` | 브라우저에서 사진을 담거나 그림을 그리는 화면 |
| 배열 | 여러 값을 순서대로 담은 목록 |
| 문자열 (`string`) | 글자와 숫자를 이어 적은 데이터 |
| `void` | 함수가 돌려주는 결과가 없음 |
| URL | 인터넷에서 사진이나 화면을 여는 주소 |
| 픽셀 | 사진을 이루는 작은 점 하나. 점마다 빨강·초록·파랑 밝기 값이 있습니다. |
| `ImageData` | 캔버스 사진의 픽셀 색상 값을 담은 자료 |
| `clamp` | 숫자가 정해 둔 범위(여기서는 0~255)를 벗어나지 않게 맞추는 계산 |

함수의 `입력`은 함수에 넣는 값이고, `출력`은 함수가 돌려주는 결과입니다.

| 파일 | 함수 이름 | 넣는 것 | 돌려받는 것 | 하는 일 |
|---|---|---|---|---|
| `js/camera.js` | `startCamera(video)` | 화면에 영상이 나올 `<video>` 요소 | 카메라 영상이 연결된 `Promise<MediaStream>`(카메라 연결 결과) | 카메라 사용을 요청하고 영상을 화면에 연결합니다. (확장 A부터; 1단계에서는 `app.js`) |
| `js/camera.js` | `captureShot(video)` | 카메라 영상이 재생 중인 `<video>` 요소 | 사진 한 장을 담은 `Promise<HTMLCanvasElement>`(그림을 그릴 수 있는 화면) | 현재 영상 한 장을 사진으로 캡처합니다. (확장 A부터; 1단계에서는 `app.js`) |
| `js/camera.js` | `stopCamera(video)` | 카메라 영상이 연결된 `<video>` 요소 | 없음 (`void`) | 촬영이 끝나거나 오류가 났을 때 카메라를 끕니다. (확장 A부터) |
| `js/frame.js` | `makeStrip(shots)` | 캡처 사진들의 `HTMLCanvasElement` 배열(사진 화면 목록) | 흰 바탕, 4:3 사진, 이름과 오늘 날짜가 담긴 세로 프레임 `HTMLCanvasElement` | 사진을 위에서부터 세로로 놓고 프레임 아래에 제목과 날짜를 그립니다. (확장 A부터) |
| `js/filters.js` | `clamp(value)` | 색 밝기 숫자 | 0~255 범위의 숫자 | 색상 값이 화면에서 쓸 수 있는 범위를 벗어나지 않도록 맞춥니다. (확장 B부터) |
| `js/filters.js` | `FILTERS` 목록 | 없음 | 각 필터의 `name`, 화면에 보일 `label`, `apply(r, g, b)`가 계산한 `{r, g, b}` 색상 목록 | 원본·흑백·세피아·따뜻하게·시원하게·화사하게 필터 정보를 제공합니다. (확장 B부터) |
| `js/filters.js` | `applyFilter(canvas, filterName)` | 원본 사진 캔버스, `FILTERS`의 필터 이름 | 원본을 변경하지 않고 새로 만든 필터 적용 캔버스 | 픽셀 색을 계산해 새 캔버스에 적용합니다. (확장 B부터) |
| `js/upload.js` | `uploadPhoto(canvas)` | 최종 사진인 `HTMLCanvasElement` | QR 코드가 가리킬 사진 주소(URL) 문자열을 담은 `Promise<string>` | 사진을 `photos` 버킷에 올리고 접근 주소를 돌려줍니다. (확장 C부터) |
| `js/upload.js` | `drawQrCode(element, url)` | QR 코드를 표시할 화면 요소, 사진 주소(URL) 문자열 | 없음 (`void`) | 휴대폰으로 읽을 수 있도록 사진 주소의 QR 코드를 화면에 그립니다. (확장 C부터) |
| `js/app.js` | `initApp()` | 없음 (페이지의 버튼·영상·결과 화면 요소와 사용할 기능 함수를 직접 가져옵니다.) | 없음 (`void`) | 버튼 동작을 연결하고, 입력에 따라 촬영부터 결과 표시 또는 오류 안내까지 이어지도록 합니다. (1단계, 확장 기능에 따라 연결 추가) |
| `js/app.js` | `runCountdown(countdown, status)` | 카운트다운과 안내 문구를 표시할 화면 요소 | 끝나면 완료되는 `Promise<void>` | 사진을 찍기 전에 5초 숫자를 보여 줍니다. (1단계부터) |
| `js/app.js` | `renderResult()` | `state.shots` 원본 사진 목록과 `state.filter` 선택 이름 | 화면의 최종 프레임 갱신 | 사진마다 `applyFilter()`를 새로 실행하고, 필터 사진들만 `makeStrip()`으로 합칩니다. 프레임 바탕과 글씨에는 필터를 입히지 않습니다. (확장 B부터) |

`initApp()`은 페이지가 준비된 뒤 한 번 실행해 화면 요소를 찾고 버튼 동작을 연결합니다. 카메라와 파일 업로드는 완료까지 시간이 걸리므로 `Promise`를 사용해 비동기로 처리합니다.

확장 B에서 앱 상태는 `state.shots`(필터를 적용하지 않은 원본 사진 목록), `state.filter`(현재 선택한 필터 이름)를 가집니다. 화면 필터 버튼은 `FILTERS` 목록에서 자동으로 만들고, 누르면 `state.filter`를 바꾼 뒤 `renderResult()`를 실행합니다. `renderResult()`는 항상 `state.shots`를 바탕으로 새 사진을 만들어 필터가 겹쳐 적용되지 않게 합니다.

## 5. 데이터 흐름

`initApp()`이 화면 동작을 연결한 뒤, 카메라 영상 → `video` → `captureShot(video)` → 촬영 사진 목록 → `makeStrip(shots)`(확장 A부터) → `applyFilter(canvas, filterName)`(확장 B부터) → `uploadPhoto(canvas)`(확장 C부터) → 사진 주소(URL) → `drawQrCode(element, url)` → 휴대폰에서 QR 코드 읽기의 순서로 이어집니다.

1단계에서는 카메라 촬영 함수가 `js/app.js` 안에 있습니다. 확장 A에서는 같은 `startCamera(video)`, `captureShot(video)` 함수를 `js/camera.js`로 옮기고 `stopCamera(video)`를 추가합니다. 선택한 컷 수만큼 촬영한 사진은 미리보기로 보여 주고, 모두 찍으면 `makeStrip(shots)`로 한 장의 세로 프레임을 만듭니다.

## 6. 지켜야 할 결정

- **카메라 사용 조건:** 웹 브라우저는 보안 때문에 HTTPS 또는 내 PC에서 연 파일(`file://`)에서만 카메라를 켤 수 있습니다. 일반 HTTP 주소에서는 동작하지 않을 수 있습니다.
- **스크립트 불러오는 순서:** `<script type="module">`은 쓰지 않습니다. 일반 `<script defer src="...">`를 사용하고, 필요한 외부 CDN 라이브러리를 먼저 불러온 다음 프로젝트 파일을 의존 순서대로 불러옵니다. `defer`는 HTML을 읽는 동안 스크립트를 준비하고, 적힌 순서대로 실행하게 합니다.
  - 1단계: `js/app.js` (카메라 기능 포함)
  - 확장 A: `js/camera.js` → `js/frame.js` → `js/app.js`
  - 확장 B: `js/camera.js` → `js/frame.js` → `js/filters.js` → `js/app.js`
  - 확장 C: 필요한 CDN 라이브러리(Supabase, QR 코드) → `js/config.js` → `js/camera.js` → `js/frame.js` → `js/filters.js` → `js/upload.js` → `js/app.js`
- **사진 보관:** 사진은 학생이 지우기 전까지 Storage에 보관하는 것을 목표로 합니다. 자동 만료는 설정하지 않습니다. 업로드만 허용하는 정책에서는 웹 화면에서 삭제할 수 없으므로, 삭제는 Supabase 대시보드에서 직접 하는 것으로 시작합니다.
- **QR 코드와 공개 범위:** QR 코드가 사진 주소를 열 수 있어야 합니다. `photos` 버킷을 공개로 설정하면 주소를 아는 사람은 사진을 볼 수 있습니다. 업로드 정책만 두더라도 공개 버킷의 읽기 동작은 별도로 고려해야 하므로, 확장 C에서 공개 범위와 삭제 방법을 사용자에게 안내하고 확인합니다. `sb_secret_` 비밀 키는 브라우저 코드에 넣지 않습니다.
